### 3. No Prerequisites Validation
**Files:** `run_frontend.py`, `main.py`  
**Impact:** Users get cryptic errors

System starts without checking if Tesseract or Ollama are installed. Users see confusing errors like:
- "FileNotFoundError: tesseract is not installed"
- "ConnectionError: Ollama not running"

**Fix Required:** Add startup validation that checks:
1. Tesseract is installed and on PATH
2. Ollama is running on localhost:11434
3. Required model (qwen2.5:3b) is available
4. Python version is 3.10+

---

### 4. SQL Injection Vulnerability
**File:** `rag/sql_retriever.py`  
**Severity:** SECURITY CRITICAL

System generates SQL from user input via LLM, then executes directly:
```python
query = "SELECT * FROM invoices WHERE ..."  # Generated by LLM
results = conn.execute(query)  # ❌ No validation!
```

**Attack Example:**
User asks: "Show invoices; DROP TABLE invoices; --"  
LLM might generate: `SELECT * FROM invoices; DROP TABLE invoices; --`

**Fix Required:**
1. Validate generated SQL against whitelist of allowed patterns
2. Use parameterized queries where possible
3. Consider read-only database connection
4. Add SQL parsing and sanitization

---

### 5. Session Data Loss (Silent Failures)
**File:** `rag/qa_chain.py:237-253`  
**Impact:** Conversation history lost without user notification

```python
except Exception as e:
    logger.warning("Could not save session %s: %s", memory.session_id, e)
    # ❌ No user notification!
```

Users won't know their conversation wasn't saved until it's lost.

**Fix Required:**
- Return success/failure status from save operations
- Show warning in UI when save fails
- Add retry logic for transient failures
